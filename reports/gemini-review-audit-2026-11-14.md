# Audit of Gemini’s generation and review assessment

**Scope.** This checks the pasted report against Kalainova at `aed28d3` (2026-11-14), the local source, the current product decisions, and the research/tool sources named below. The report Gemini read is not pinned to a commit, so this audit cannot establish which snapshot it inspected. `origin/main` is now at `2813818`, three commits ahead of this checkout; those commits changed the face-identity reader and some audio/QA behavior. I note material drift where relevant.

**Rubric.** Gemini mostly scores Kalainova as if it were a frontier video-generation lab building a self-healing, autonomous multimodal generator. Kalainova’s stated target is different: coordinate rented models into accountable finished work, keep a human in control of taste and publication, control spend, and only promote measurements after they correlate with human verdicts. The target still includes quality; the difference changes which gaps deserve engineering time.

## Overall assessment

Gemini finds several real capability gaps: the engine does not own a 3D scene or explicit camera-pose control; its current review judge receives sampled images rather than a video stream; it does not have a video-conditioned Foley stage; and a bad shot is mainly handled with a new take or a human edit rather than generative region repair.

The report is unreliable as an implementation plan. It repeatedly treats research methods and benchmark scores as turnkey production components, assigns them unsupported guarantees and thresholds, and omits existing features. Most seriously, it recommends hard QA gates and new adapters without first calibrating them against accepted/rejected Kalainova work, contrary to ADR 0011. Some claims about output quality (“frequently mute,” “70% savings”) cannot be checked here: `$KALAINOVA_HOME` is unset, so there are no private jobs, verdicts, or rendered pieces to inspect.

My read: **use the report as a list of experiments, not as a gap analysis or roadmap.** The first implementation priority should be correctness of the existing take and review signals, then a small, measured audio/video evaluation pilot. The 3DGS, shared-latent-codec, and autonomous-inpainting proposals are research programs, not near-term fixes.

## Findings by claim

| Gemini claim | Audit | What the code and research support |
|---|---|---|
| “Disjoint sequential waterfall”; no cross-modal attention or native audio | **Mostly right, overstated** | Kalainova orchestrates stages and uses FFmpeg for final assembly; it is not one joint AV latent model. But it does support optional audio generated with a video clip (`brief.clip_audio`), generated per-shot ambience/SFX, separate dialogue/music/effects/ambience buses, and on-camera lip-sync. The real gap is narrower: there is no dedicated *video-conditioned Foley pass* over the finished clip, and a text-described ambience/SFX is not frame-level event alignment. [shotmake.py](../src/kalainova/shotmake.py), [render/sound.py](../src/kalainova/render/sound.py). Meta’s Movie Gen Audio is itself described as an audio model conditioned on video and optional text; the Movie Gen work is a family of models, not evidence that every production engine needs a shared joint AV decoder. [Meta Movie Gen research](https://ai.meta.com/research/publications/movie-gen-a-cast-of-media-foundation-models/), [Meta announcement](https://ai.meta.com/blog/movie-gen-media-foundation-models-generative-ai-video/). |
| “Generic beds rather than synchronized Foley”; pieces frequently feel mute | **Gap partly real; output claim unverified** | The source has per-shot audio extraction when a video model returns audio, text-to-SFX, ambience, music, and mixing. It does not derive sound cues from video frames or measure their temporal match. No production output was available to substantiate “frequently.” FoleyCrafter and MMAudio are relevant V2A research systems, but are not the same thing as Movie Gen’s audio model and do not justify a default paid pass for every job. [FoleyCrafter paper](https://arxiv.org/abs/2407.01494), [MMAudio paper](https://arxiv.org/abs/2412.15322). |
| Continuity is just prompt reference injection plus a face-distance heuristic | **Wrong by omission; capability gap remains** | Continuity also uses frozen kit versions, locked job references, repeated character/place/prop descriptions, image references where a vendor accepts them, optional last-frame conditioning, and kit/face checks. It is fair that Kalainova does not modify a vendor’s DiT attention layers and cannot promise robust identity through arbitrary view changes. ConsisID and StoryDiffusion are model-side methods tied to particular generation stacks, not adapters that can be applied to a black-box hosted video API. [consistency/kit flow](../src/kalainova/consistency.py), [shotmake.py](../src/kalainova/shotmake.py), [ConsisID paper](https://openaccess.thecvf.com/content/CVPR2025/papers/Yuan_Identity-Preserving_Text-to-Video_Generation_by_Frequency_Decomposition_CVPR_2025_paper.pdf), [StoryDiffusion paper](https://proceedings.neurips.cc/paper_files/paper/2024/hash/c7138635035501eb71b0adf6ddc319d6-Abstract-Conference.html). |
| ConsisID encodes low/high-frequency identity features in shallow/deep DiT blocks | **Broadly grounded, overspecified** | ConsisID does separate global/low-frequency and local/high-frequency face information and integrates features into a DiT. That is a research architecture, with training and model integration requirements. Its paper does not imply a universal identity “guarantee,” nor that it can be added to hosted providers. The Gemini report’s exact description of shallow versus deep layers should be tied to the paper’s implementation details before repeating it as a portable recipe. |
| Textual pans hallucinate; 6-DoF Plücker conditioning gives exact camera movement | **Real control gap; guarantee false** | This checkout exposes motion prompts and still-image pan/zoom, plus first/last frames only when the selected provider supports them. It has no general camera-pose/trajectory input. Research control methods can give stronger conditioning for compatible models, but a pose parameter is not a guarantee that generated pixels obey the camera path. A new seam would need a provider that actually accepts the representation. |
| First/last-frame conditioning creates “flawless” transitions | **Overclaim** | The engine sends an end image only to models whose adapter declares support, and records when it was not used. This gives a constraint, not continuity across independently rendered shots. It cannot make an unreliable video model “flawless.” [direct-a-shot guide](../docs/how-to/direct-a-shot.md). |
| Replace FFmpeg/HyperFrames with Remotion/WebCodecs/Skia for faster distributed rendering | **Not established as an engine defect** | Remotion is a viable declarative browser renderer and offers Lambda chunking. Its docs describe headless browser tabs screenshotting frames, FFmpeg encoding, and parallel chunk workers; they do not support the report’s blanket “60-second render in under 3 seconds” claim or imply GPU rendering by default. Kalainova already has a render plan, fixed FFmpeg operations, HyperFrames graphics, OpenTimelineIO, and a dependency-keyed cache that reuses unchanged outputs. Replacing it makes sense only if representative render profiles show the current compiler is the bottleneck. [Remotion concurrency](https://www.remotion.dev/docs/lambda/concurrency), [Remotion architecture](https://www.remotion.dev/docs/lambda/how-lambda-works), [render cache](../src/kalainova/render/cache.py). |
| Handcrafted metrics miss perceptual artifacts; add DOVER/FAST-VQA/VBench | **Valid blind spot; proposed substitution is wrong** | The studio bar already includes more than container checks: stutter, repetition, motion after camera compensation, identity, sound, safe zones, cuts, plus sampled-frame human/LLM review. It still cannot reliably judge realism, taste, or all temporal defects. DOVER separates technical and aesthetic judgments for user-generated videos; FAST-VQA is an efficient learned VQA model; VBench is primarily a benchmark suite with dimension-specific evaluators and human preference annotation. None is a universal pass/fail score for arbitrary short generative shots. The VBench paper explicitly situates its metric suite as a model benchmark and validates human alignment on its own test settings. [DOVER](https://arxiv.org/abs/2211.04894), [FAST-VQA](https://arxiv.org/abs/2207.02595), [VBench](https://openaccess.thecvf.com/content/CVPR2024/papers/Huang_VBench_Comprehensive_Benchmark_Suite_for_Video_Generative_Models_CVPR_2024_paper.pdf). |
| DOVER/FAST-VQA correlate “>0.85” and should replace current checks | **Unsupported as stated** | Correlation varies by dataset, split, metric, and evaluator; “near-zero latency” is not a defensible general description of learned VQA inference. These models assess quality dimensions, not whether a prompt’s hand has six fingers, whether a specific character stayed on-model, or whether an action happened at the intended time. Run candidates beside existing metrics on Kalainova’s own reviewed samples, record runtime and failure cases, and keep them advisory until they separate human verdicts. ADR 0011 already requires this. |
| No lip-sync verification; gate at LSE-C < 5.5 | **Gap real; threshold recommendation wrong** | There is a rented lip-sync generation capability, but no automatic detector that verifies the final generated mouth against the voice. LSE-C/LSE-D are useful SyncNet-derived research/evaluation metrics. They are not “lip-sync error” in the sense of a calibrated universal threshold: LSE-C is a confidence/correlation measure, LSE-D a feature-distance measure, and their values depend on face visibility, frame rate, preprocessing, model version, and evaluation domain. The cited original work reports relative comparisons; it does not establish 5.5 as a production gate for Kalainova. Start with warning-only measurements on on-camera speech and human verdicts. [Wav2Lip paper](https://researchportal.bath.ac.uk/files/211225619/Wav2Lip_ACMMM_20_camera_ready_2_.pdf). |
| VBench-2.0 directly checks anatomy with MediaPipe/DWPose, flow, and physical laws | **Partly true premise, wrong method attribution** | VBench-2.0 does assess human fidelity, controllability, creativity, physics, and commonsense, with generalist VLM/LLM and specialist anomaly-detection methods. That is different from the report’s specific recipe of MediaPipe/DWPose, RAFT warping, and falling-object trajectory checks as if these were the benchmark’s standard plug-in detectors. It is also a benchmark framework, not a drop-in bar. [VBench-2.0 paper](https://arxiv.org/abs/2503.21755). |
| ImageBind cosine similarity gates “does the sound match the picture?” | **Research signal, not a dependable gate** | Shared embedding similarity can surface semantic mismatch, but image/audio sampling and embedding-space similarity do not prove that an event is correctly timed, that no sound is missing, or that intentional silence is wrong. There is no single universal threshold. It is a candidate offline signal to compare with human-labelled shots, especially with a “not applicable/intentional silence” case. ImageBind’s paper describes a shared embedding across modalities and emergent retrieval/recognition uses; it does not specify a universal audiovisual-consistency gate. [ImageBind paper](https://openaccess.thecvf.com/content/CVPR2023/papers/Girdhar_ImageBind_One_Embedding_Space_To_Bind_Them_All_CVPR_2023_paper.pdf). |
| Current QA judge is static and loses all temporal localization | **Partly right** | The configured Anthropic adapter sends JPEG/PNG images; it does not send a video stream. QA supplies a contact sheet, a multi-frame motion strip, and a cut strip is also produced for human review. The rubric asks about time/region, and `shot_problems` requires localization to retain a detected problem. However, `findings_from_judge` then persists only shot id, problem names, note, and suggested prompt change; it drops structured region/time. So the report is right that richer defect localization is missing downstream, but wrong to say the judge sees only a single static contact sheet. [qa.py](../src/kalainova/qa.py), [qachecks.py](../src/kalainova/qachecks.py), [QA rubric](../prompts/qa_rubric.md). |
| Native video MLLMs give reliable spatio-temporal boxes/tubes | **Plausible experiment, not guaranteed capability** | A model accepting video input may make temporal reasoning easier, but it still needs a validated defect taxonomy, timestamps mapped to the edit manifest, confidence/abstention, and human review. A JSON schema asking for boxes does not make their locations accurate. The configured provider currently accepts images, not video; another provider/adapter would be real implementation work. |
| Passive findings; whole-shot reroll; targeted inpainting saves up to 70% | **Partial diagnosis, unsupported savings claim** | Kalainova stores findings, can retake one shot, keeps attempts, can let a person patch an edit, and caches unchanged render steps. It has no generative region-inpainting loop. ProPainter is a video inpainting tool that needs masks and temporal inputs; that does not establish compatibility with generated provider outputs or the 70% cost/latency figure. Before a repair loop, preserve the critic’s time/region and make the fix a human-reviewed candidate. Research/demo performance does not prove lower total cost once localization errors, masks, retries, and re-QA are included. |
| Automatically snap cuts ±100ms to beats/transients | **Possible, but conflicts with current semantics if automatic** | The engine computes `edit.cuts_on_beat` as a warning and records cut distance to beat grid. It intentionally treats beat fit as feel, not correctness; a fixed tolerance can damage speech cadence or a deliberate edit. A previewable proposal with a human accept/undo is safer than mutation during compile. |
| 3DGS scene anchors yield absolute continuity and zero hallucination | **Speculative and false guarantee** | A persistent 3D representation can help repeatable camera views, but reconstruction/generation, appearance changes, occlusion, motion, and projection still fail. It adds a large local rendering/training/asset pipeline that does not fit the current rent-model, prove-before-adopting policy without a real job demanding it. “Zero spatial hallucination” is not supportable. |
| Shared audio-video codecs (Cosmos/MAGVIT) should replace PNG/MP4/WAV flow | **Category error** | These are learned representation/model components, not generic interchangeable timeline codecs that let this orchestration engine edit audio/video latents and decode a delivery master. That would mean owning/replacing model internals and representation compatibility. It does not solve a demonstrated bottleneck in current renders. |
| Dynamic spectral de-masking is a quick FFmpeg upgrade | **Possible craft experiment, not a missing capability** | Current mixing already measures voice level, applies a designed music pocket and sidechain ducking, then loudness-normalizes. Multiband/dynamic EQ can sound better on some mixes and worse on others; a filter graph is not an automatic upgrade. Compare blind listening and voice intelligibility across approved mixes before changing the default. [sound.py](../src/kalainova/render/sound.py). |

## Higher-priority code findings exposed by this audit

These are more actionable than adding another model score:

1. **Unreadable or too-short motion samples can be treated as successful.** In `takes.assess_clip`, decode errors return `(unread=True, ok=True)`, and too-short clips also return `ok=True`. That value then means both “don’t spend another paid take” and “this take satisfies the motion promise.” `motion_break` returns early for `take.ok`, so an unreadable clip can escape the promise-break path. Split assessment state (pass / fail / unmeasurable) from retry policy. Add deterministic regression coverage for decode failure, missing metadata, and clips too short to score. [takes.py](../src/kalainova/takes.py#L154), [shotmake.py](../src/kalainova/shotmake.py#L313).
2. **Automatic take selection optimizes the motion score only.** `_best()` selects the passing take with the highest generic `score`, currently shot motion. A more animated but visibly worse shot can therefore beat a calmer good one. Keep motion as a minimum promise, not a quality objective; use human choice or a calibrated multi-signal ranking. [takes.py](../src/kalainova/takes.py#L88).
3. **The judge’s structured location is discarded before repair/review reuse.** QA requires location before retaining a problem, but findings omit region/time. Preserve validated location, source frame, confidence, and schema version so a person can jump to the defect and a later repair proposal can target it. [qachecks.py](../src/kalainova/qachecks.py#L182), [qachecks.py](../src/kalainova/qachecks.py#L202).
4. **The VLM judge is advisory and errors become warnings.** That is consistent with the human gate, but test/reporting should keep judge coverage visible: “not judged,” “judge errored,” “no applicable shot,” and “judge found no issue” must remain different states. [qa.py](../src/kalainova/qa.py#L382).

The checkout has strong deterministic tests for synthetic motion, audio signals, provider contracts, render behavior, and schema boundaries. The risk is not simply “too few tests”; it is coverage of ambiguous states and insufficient calibration on real generated outputs. The narrow missing take-state cases above deserve fast unit tests. Learned metrics and real model calls should live in a separate, opt-in evaluation job, never in the normal CI suite. Existing CI was reported locally at about 4m27s with 18 workers; adding PyTorch/vision models to that path would make it slower and less deterministic. No tests were run as part of this audit.

## Recommended sequence

| Priority | Work | Why / exit condition |
|---|---|---|
| **P0** | Make take assessment tri-state and ensure unmeasurable motion cannot satisfy the motion promise. Test the cases cheaply. | Prevents a false pass before adding new QA. |
| **P0** | Treat motion as an eligibility floor, not “best quality”; document what automatic take selection actually means. | Avoids selecting the most active but least usable take. |
| **P1** | Preserve judge timestamps/regions and abstention in findings; map them back to the edit manifest. | Improves present human review and creates a safe base for repair. |
| **P1** | Pilot one optional video-conditioned Foley route on a fixed private set, with text-to-SFX/ambience and existing sound mix as baselines. Record human fit, synchronization, failure/intentional-silence cases, cost, and wall time. | Tests the strongest audio opportunity without assuming every shot needs it. Keep artifacts private and spend capped. |
| **P1** | Evaluate one learned video-quality signal and one AV-sync signal on reviewed shots, outside CI. Report pairwise agreement, false alarms, unmeasurable rate, and runtime against current readings. | ADR 0011 says a signal stays only if it separates good from bad on actual reviewed samples. Only then consider warning thresholds. |
| **P2** | Try video-native judge input or a richer temporal sheet on a small set; compare localization quality and review time. | Adopt only if it yields better human-verified fault localization at acceptable cost. |
| **Defer** | 3DGS anchors, shared AV latent codec, blanket inpainting, mandatory ConsisID, mandatory DOVER/SyncNet. | High integration/cost, model-specific, no production evidence or customer requirement yet. |

This sequence matches accepted decisions: rent generation/identity/lip-sync where providers already do it well; add a seam only with two real adapters; keep measurements advisory until verdict-calibrated; keep the spend cap and human approval. It also matches the studio goal’s open questions: there is no verified real-run evidence yet for motion, song quality, or which readings predict a human verdict.

- `$KALAINOVA_HOME` is unset in this environment. I did not inspect actual `qa.json`, approvals, verdicts, or rendered media, so I cannot confirm whether Kalainova outputs have the alleged audio/continuity problems.
- I did not run a model, publish anything, or run the test suite.
- The local review branch is three commits behind `origin/main`. The later face-reader changes keep identity recognition optional and command-backed rather than making ConsisID relevant; re-run this audit against the operator’s intended branch before turning findings into implementation work.
